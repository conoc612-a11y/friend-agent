# 한 줄 요약
무료로 열어 둔 에이전트 서비스가 사용자 한 명의 300개 메시지로 한 달 원가 5,940원(300×0.66원)이 나간다는 걸 Langfuse로 확인했고, 그 숫자로 크레딧 한도와 가격을 정하고, 원장을 쌓고, 같은 요청이 두 번 와도 한 번만 처리되도록 세 겹을 만들었다.

---

## 시작 질문 답
하루 300개 사용자는 한 달 원가 약 5,940원, 악용 계정(하루 3,000개)은 약 59,400원. 메시지 한 건은 몇 원이지만 사용자 수가 아니라 **사용량**이 원가를 결정한다. 막으려면 메시지 한 건의 원가를 알고, 무료 한도와 전환율로 손익을 관리하고, 넘으면 결제를 받도록 해야 한다.

---

## 원가표 (Langfuse 실측, 16턴 대화 1개)
- 모델: gpt-4o-mini
- 메시지 1건 평균: $0.000414 ≈ **0.60원**
- 상위 10%: 0.66~0.71원
- 10번째 이후: 0.66원 (+42% vs 첫 0.46원)
- 가장 비싼 단계: **도구 고르기(43%)** > 답 만들기(35%) > 기억 정리(22%)

교안 예측과 달리 도구 설명이 매 호출 입력에 포함되어 도구 고르기가 가장 비쌌다. 원가 줄이면 1순위는 **도구 설명 다이어트/캐싱**.

---

## 모델 비교 (10개 메시지, 새 사용자)
| 항목 | gpt-4o-mini | gpt-4.1 |
|---|---|---|
| 10개 비용 | 6원 | 83원 |
| 1건 평균 | 0.61원 | 8.3원 (13.7배) |
| 답 더 나음 | 0 | **6/10** (날짜 계산, 맥락 이어가기) |

큰 모델은 답이 더 나으나 13.7배 비싸다. 지금은 작은 모델 유지, 큰 모델은 **답 만들기(reply)만** 고려.

## 가격 · 한도
- 원가 0.63원 → 크레딧 1개 ≈ 8.3원 순이익 (10,000원/1,200개, 수수료 포함)
- 큰 모델(8.3원)은 크레딧 1개로 손해 → 큰 모델 메시지만 더 받기 검토
- 무료 한도: **가입 시 30개** (초기 원가 약 20원). 전환율 재기 전 작게.
- 상품: 100/550/1,200개 (1,000/5,000/10,000원)

계산기 확인: 가격 2배는 적자 30만→258만 원 줄이지만, **무료 한도 10→3개는 거의 본전**. 전환율이 결정하므로 처음엔 작게 잡고 재며 늘린다.

## 크레딧 원장 (`supabase/migrations/0002_credits.sql`)
- 테이블: `credit_ledger` (user_id, change, reason, `reference` UNIQUE, created_at)
- RLS 켜기, 공개 정책 없음
- 차감: `/api/chat` 메시지 받자마자 → 잠금 1번 → 잔액 확인 → −1 (동시 10개 → 1만 통과)
- 실패: `chat_refund` +1 (지우지 않음, 쌓기만)
- 잔액 0 → `402` (balance 포함)
- 위기 표현: 차감 없이 답함

## 토스 결제 (`app/payment.py` · `static/index.html`)
- `.env`: `test_gck_doc_...` / `test_gsk_doc_...`
- 승인 `POST /v1/payments/confirm`: `Basic base64("시크릿:")` + `Idempotency-Key: <주문번호>`
- 화면: 사이드바 `💰 크레딧` 버튼 → 팝업(`borrowance`, 상품) → 위젯 `TossPayments` → `/api/orders` → `/api/payments/confirm`
- 브라우저: 1,000원 결제 → 잔액 30→130 (`order:` +100 줄)
- 서버 로그: `tgen_...` 가림 → `paymentKey` 0회 (확인 목록으로 `access` 필터 추가)
- 같은 요청 3번 → 승인 1번 (멱등); 금액 바꾼 요청 → 토스 호출 0 (400)

## 멱등성 세 겹
1. 주문 상태 확인 (`get_order`) → 완료면 첫 결과 반환
2. 원장 `reference` UNIQUE (`ref`) → 같은 참조 두 번 쌓기 불가
3. Toss `Idempotency-Key` (`order_id`) → 같은 키 → 409(처리 중) → 재시도 → 첫 응답 재사용

## 공격 테스트 (가짜 LLM, `STORAGE=memory`)
